# 架构说明

## 玩家体验

2–4 名玩家通过房间码加入，空位可由房主动态加入 AI。所有玩家看到同一局状态，但只有当前玩家能提交有效操作；秘密选角阶段只向本人显示选择内容。房主执行全部随机数与规则判定，避免不同设备各自计算导致分歧。

## 模块边界

- `game/engine.ts` 是唯一规则状态写入者。输入为 `GameAction`，输出为新的 `GameState`。
- `game/racers.ts` 保存 36 名角色的不可变定义；运行时位置、绊倒、得分等与定义分离。
- `network/session.ts` 只处理连接、身份、动作转发和玩家视图，不包含比赛规则。
- `three/trackScene.ts` 只呈现状态，不修改游戏。
- `ui/render.ts` 展示状态并发送玩家意图，不拥有规则。

## 联机协议

```text
客人操作 → WebRTC DataConnection → 房主 validate/apply → 针对每名玩家投影视图 → 广播
```

身份保存在 `sessionStorage`：同一浏览器可开四个独立标签页测试，当前标签页刷新后仍能用同一身份重连。房主页面是临时服务器，关闭后不保留局面。

## 规则适配决策

- 赛道数字长度为 30 格，第二弯道阈值为第 16 格。
- 四局奖杯为金杯 4/6/8/10 分、银花 2/3/4/5 分。
- 数字版采用统一的 2–4 人轻量模式：每名选手始终招募 4 名角色、每局派出 1 名；蛇形顺序和公共牌池按房间人数动态生成。这样可让 AI 与真人自由替换，同时保持手机回合简洁。
- 桌游中无需策略判断或通常只有单一有利结果的可选能力会自动触发。
- 需要明确目标或会改变风险的能力通过选择面板处理，例如天才预测、幕后主脑预测、换位、催眠、第三轮传送、重掷和火箭加倍。
- 连锁能力设置深度上限，遵循规则书的“无限循环只完成一次后结束”原则。

## 正式版扩展点

1. 用自托管 PeerServer + TURN 替换公共信令。
2. 增加房间快照存储、房主迁移和掉线计时。
3. 把自动选择能力改为完整的玩家确认窗口和响应优先级队列。
4. 替换经授权的正式角色插画、动画、音效与多语言文本。
